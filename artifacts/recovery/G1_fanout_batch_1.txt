[CASE 01 / BATCH1-01] com_bridge.py CLI Fallback compile_project Claims Success on Toolchain Presence Without Compiling
- Component: Automation & CLI Bridge
- Target File: src/automation/com_bridge.py (Lines 333-344)
- Trigger Condition:
  Invoking CscapeComBridge.compile_project(project_path) when COM server is absent
  (self.mode != 'com') or COM compilation raises an exception, dropping into CLI fallback.
- Vulnerability Mechanism:
  Under CLI fallback, compile_project executes:
      install_info = self.cli_runner.verify_installation()
      return {
          'status': 'success' if install_info.is_installed else 'failed',
          'mode': 'cli_fallback', ...
      }
  If Cscape or Straton toolchain files exist on disk, install_info.is_installed is True,
  and the bridge returns status: 'success' without ever executing a compiler binary,
  checking syntax, or generating build outputs!
- Fail-Closed Directive:
  CLI fallback must execute genuine compiler passes or fail closed immediately returning
  status: 'failed', error_code: 'CLI_COMPILATION_UNAVAILABLE', and non-empty errors list
  specifying that uncompiled toolchain presence cannot be treated as compilation success.

[CASE 02 / BATCH1-02] cscape_add_st_pou / cscape_insert_st - Adding POU to Non-Existent Project Creates Spurious Folders and Claims Success
- Component: FastMCP Project Management & POU Staging
- Target File: src/mcp/tools.py (Lines 2354-2405, 1048-1074)
- Trigger Condition:
  Invoking cscape_add_st_pou(project_name='GhostProject', pou_name='Logic', pou_type='program', code='...')
  or cscape_insert_st with a target_project_path pointing to a non-existent directory.
- Vulnerability Mechanism:
  1. cscape_add_st_pou validates clean_pou_name, but NEVER validates project_name
     using SafetyGuard.validate_project_name(project_name).
  2. target_dir = WORKSPACE_ROOT / 'artifacts' / 'projects' / project_name is passed
     to cscape_insert_st.
  3. cscape_insert_st executes pous_dir.mkdir(parents=True, exist_ok=True) and writes
     pou_file = pous_dir / f'{clean_pou_name}.st'.
  4. If the code has valid syntax, it returns status: 'success', success: True, creating
     an unmanaged ghost project directory containing only pous/ on disk.
- Fail-Closed Directive:
  cscape_add_st_pou must validate project_name and verify that the project directory
  and its native project container (.csp or cscape_project.json) actually exist on disk.
  If missing, fail closed immediately: status: 'failed', error_code: 'PROJECT_NOT_FOUND'.
  cscape_insert_st must refuse to mkdir or mutate disk if target_project_path does not exist.

[CASE 03 / BATCH1-03] STParser.validate - Empty POU or Arbitrary Snippet Without Declarations Emits WARN_EMPTY_POU and Returns is_valid=True
- Component: IEC 61131-3 Structured Text Parser & AST Engine
- Target File: src/iec/st_parser.py (Lines 1025-1032, 1064)
- Trigger Condition:
  Passing source code lacking POU blocks (PROGRAM, FUNCTION_BLOCK, FUNCTION) and lacking
  assignments or VAR declarations (e.g. arbitrary invalid identifiers, comments only, or ';;;').
- Vulnerability Mechanism:

      self.issues.append(
          STIssue(
              severity=IssueSeverity.WARNING,
              code='WARN_EMPTY_POU',
              message='No PROGRAM, FUNCTION_BLOCK, or FUNCTION definitions found in Structured Text.',
              line=1,
          )
      )
  At line 1064:

- Fail-Closed Directive:

  fatal error: severity=IssueSeverity.ERROR, code='ERR_NO_POU_FOUND', and return is_valid=False.
