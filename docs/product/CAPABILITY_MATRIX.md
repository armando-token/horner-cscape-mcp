### 1.1 Live MCP / GUI Gap Audit Summary & Honest Partial Classification

While continuous stay-open execution of Cscape 10.2 has been demonstrated on live hardware (PID 7616, PID 15240, PID 14580, and active supervisor PID 3120 holding TankLevelClosedLoop.csp), full autonomous GUI interaction remains inherently constrained. In accordance with the **Fail-Closed Audit Policy**, all Live GUI automation capabilities are **HONESTLY CLASSIFIED AS PARTIAL**.

The technical root causes and operational gaps are thoroughly audited in [docs/live_mcp_gui_gaps.md](file:///C:/HornerAI/horner-cscape-mcp/docs/live_mcp_gui_gaps.md):
1. **Lack of COM/IDispatch Automation**: Cscape 10.2 (x86 PE) exposes no COM Automation server (IDispatch) CLSID. All live GUI interaction must rely on low-level Win32 window message pumping (WM_COMMAND, SendMessageTimeoutW), UI Automation, and clipboard injection.
2. **Desktop Session & Station Context**: Win32 GUI controls require explicit attachment to the active Window Station and Desktop (winsta0\\Default). Non-interactive CI runners, SSH daemons, or headless background services cannot interact with the GUI without the keepalive supervisor.
3. **Single-Session Project Concurrency**: Cscape operates as a single-document/single-active-project MFC application. Creating a new project (cscape_new_iec_project) or opening another file (cscape_open_project) disrupts the active project session (TankLevelClosedLoop.csp) and introduces modal confirmation prompts.
4. **Editor Focus & Clipboard Sensitivity**: Live Structured Text POU insertion (cscape_insert_st) relies on clipboard WM_PASTE into the focused W5EditST child window. Any shift in window focus causes injection failure or misdirection.
5. **Modal Dialog Traps & Window Disablement**: Live compilation Error Check (ID_PROGRAM_ERRORCHECK = 32826) frequently spawns modal warning dialogs (#32770) that invoke EnableWindow(main_hwnd, FALSE), temporarily disabling the main window until dismissed by an active modal dialog sweeper thread.
6. **ST-to-LD Conversion Impossibility**: Native conversion between ST and LD is fundamentally **BLOCKED (Doc Only)** in Cscape 10.2 (detailed in [docs/st_to_ld_conversion_blocked.md](file:///C:/HornerAI/horner-cscape-mcp/docs/st_to_ld_conversion_blocked.md)).

### Why These Capabilities Are Invalid for Production Cscape Automation:
1. **Loose Directory vs. Compound File Binary Format (`.csp` / `.cpj`)**:  
   Horner Cscape 10.2 does not manage customer automation projects as loose directory trees with `appli.k5p` and `K5DBXS.INI`. Native Cscape projects are Microsoft Compound File Binary Format (CFBF OLE2) single-file or project packages. The legacy generators produced files that Cscape could not open as native projects.
2. **Fabricated Memory Footprints vs. Real Cscape Compilation**:  
   [`legacy_automation_project_manager.py`](file:///C:/HornerAI/horner-cscape-mcp/quarantine/straton_k5_legacy/legacy_automation_project_manager.py) claimed to compile projects by estimating memory segment sizes in pure Python, bypassing both `Cscape.exe` and `K5Cmp.dll`. This produced fabricated build metrics that did not reflect actual Cscape compiler checks. Real compilation is now handled via [`CscapeCompiler`](file:///C:/HornerAI/horner-cscape-mcp/src/cscape/compiler.py) dispatching `ID_PROGRAM_ERRORCHECK = 32826` to `Cscape.exe` or performing offline AST-level diagnostics.
3. **Standalone T5 Runtime vs. Horner OCS Firmware**:  
   The legacy code assumed target controllers could be set to `T5RTI` or `T5SIMUL` (generic Copa-Data runtime engines). Physical Horner controllers execute Horner proprietary firmware, while software simulation is conducted through [`CscapeSimulator`](file:///C:/HornerAI/horner-cscape-mcp/src/cscape/simulation.py) with accurate `%R`, `%M`, `%AI`, and `%S` clock pulses. Active schemas in `src/mcp/schemas.py` and `src/security/guard.py` now officially allowlist modern Horner OCS series (`EXL10`, `XL10`, `XL+`, `Micro OCS`, `X2`, `X4`, `X5`, `X7`, `XL4`, `XLE`, `XL7`, `EXL6`, `RCC972`, `ZX`) and deprecate `T5RTI`/`T5SIMUL`.
